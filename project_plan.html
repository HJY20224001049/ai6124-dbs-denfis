数据与目标

目标是次日对数收益 rt+1 = ln(Ct+1/Ct)，特征只用到 t 日为止的信息。方向标签由预测收益的符号给出，另设一个“不交易”死区。

  • 折内 z-score，只用训练段统计量
  • 所有指标类特征都是因果的
  • 折定义只写在 config.py 一处

DENFIS 实现要点

ECM 在标准化特征空间里增长/合并聚类；每个聚类对应一条一阶 TSK 规则；结论参数用加权 RLS（带遗忘因子）更新。

  • ECM 半径 Dthr 是主敏感参数
  • 先预测、再用已实现的当日收益更新
  • “冻结版”和“在线版”分开报告

评估协议

3 组 rolling-origin × 每組 3 个连续一年测试折，覆盖 2017–2025；2026 年 1–10 月完全不参与调参，作为最终盲测。

  • 回归：RMSE、MAE、R²、IC
  • 方向：准确率（含死区版本）
  • 组合：年化收益、Sharpe（√252）、最大回撤、换手
不要用 R² 当主指标。 日频收益接近不可预测，R² 为负是常态。主叙事放在方向准确率和含成本组合表现上，R² 如实报告即可；否则很容易把“正常结果”写成“模型失败”。

协作约定

接口先冻结，再各自实现

两个人最容易浪费时间的地方是“结果对不上”和“notebook 冲突”。用同一份配置、同一套接口、统一的预测落盘格式来解决。

config.py          # 目标定义、特征列、折区间、随机种子 —— 唯一真源
data.py            # load_prices(symbol); build_features(df) -> X, y; make_folds(...)
models/denfis.py   # class DENFIS: fit / predict / partial_fit; n_rules_
models/baselines.py# class XGBModel, LSTMModel —— 同样的 fit / predict
eval/metrics.py    # rmse, mae, r2, dir_acc, ic
eval/backtest.py   # make_signal(pred, tau); run_backtest(sig, ret, cost_bps)
eval/cv.py         # run_cv(model_factory, folds) -> results/preds_*.csv
results/           # 只写不删：preds_{model}_{fold}.csv + summary.csv
  • 预测先落盘。训练和画图解耦，分析只读 results/，任何人重跑都能复现同一张表。
  • 测试段只在最终评估时打开。超参数、阈值、特征筛选全部在训练段或内层验证里决定。
  • 每个模块先写 10 行使用示例，再写实现。接口签字后再开工，避免互相等。
  • Git 用功能分支 + PR。notebook 只由 B 在 11 月 16–17 日统一合并；开发期各写各的模块。
  • 数据缓存进仓库。CSV/parquet 只有几 MB，保证最终 notebook 离线可跑，不受 Yahoo 限流影响。
  • 每天 15 分钟同步。昨天完成什么、今天做什么、现在卡在哪里；卡住超过 2 小时就换方案。
环境已检查：Python 3.9；torch 2.8.0 是 CPU 版；xgboost 2.1.4、scikit-learn 1.6.1 已装；yfinance 未安装，今天先 pip install yfinance 并缓存数据。LSTM 不要开大，hidden 16–32、窗口 20–30 足够。
